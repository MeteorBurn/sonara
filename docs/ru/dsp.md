# Ядро DSP: низкоуровневые алгоритмы Sonara

Эта глава описывает числовой фундамент библиотеки — всё, что лежит ниже
оркестратора `analyze.rs` и модельных слоёв. Каждый раздел написан по телу
реализации в этом checkout (0.3.7, `0c2a4b3`), а не по README и не по
документации librosa. Там, где код отступает от «учебного» алгоритма, это
названо явно: пометка **Приближение** означает, что реализация упрощена
намеренно, пометка **Расхождение** — что поведение не совпадает с тем, что
обещает docstring или что ожидает читатель librosa.

Соседние главы: [оглавление](README.md) (обзор и карта модулей),
[api.md](api.md) (публичный Rust/Python API), [rhythm-tonality.md](rhythm-tonality.md)
(темп, биты, онсеты, тональность), [descriptors-models.md](descriptors-models.md)
(перцептивные дескрипторы и ML-модели). Здесь они не дублируются: модуль
`feature/rhythm.rs` (темпограммы) и всё, что выше слоя признаков, оставлено
соседям.

## 1. Соглашения и типы

Источник: [`types.rs`](../../sonara/src/types.rs), [`error.rs`](../../sonara/src/error.rs).

**Точность.** Основные сигналы и признаки используют `f32` (`Float = f32`). Комплексные значения —
`Complex<f32>`. Это осознанный выбор: Symphonia декодирует в `f32`, а f32 вдвое
дешевле по памяти. Некоторые промежуточные расчёты, например коэффициенты
K-взвешивания и префиксные суммы громкости, используют `f64`. При сравнении
с реализацией на `float64` допуск нужно выбирать для конкретного алгоритма;
единой гарантированной относительной погрешности для всего ядра нет.

**Формы массивов** (все `ndarray`):

| Псевдоним | Форма | Смысл |
| --- | --- | --- |
| `AudioBuffer` | `(n_samples,)` | моно-сигнал; обычно нормирован к `[-1, 1]`, но тип не ограничивает амплитуду |
| `MultiChannelAudio` | `(n_channels, n_samples)` | многоканальный сигнал |
| `Stft` | `(1 + n_fft/2, n_frames)` | комплексный STFT |
| `Spectrogram` | `(n_bins, n_frames)` | любой вещественный спектр (magnitude, power, mel) |
| `FilterBank` | `(n_filters, 1 + n_fft/2)` | матрица банка фильтров |

У спектральных матриц ось 0 — частота или признак, ось 1 — время.
У других матриц, например DTW и переходов HMM, оси имеют свой смысл.

**`WindowSpec`** описывает окно тремя способами: `Named("hann")`,
`Array(готовые отсчёты)` и `Parameterized("kaiser", 14.0)`.

**`PadMode`** парсится из строки (`constant`/`zero`, `edge`, `reflect`,
`symmetric`, `linear_ramp`), но реально различаются только три режима — см.
[§5](#5-stft-istft-и-спектральные-операции).

**Ошибки.** `SonaraError` разбит на группы: ввод-вывод (`AudioFile`,
`UnsupportedFormat`, `Decode`), валидация (`InvalidParameter { param, reason }`,
`ShapeMismatch`, `InvalidAudio`), вычисления (`Fft`, `ConvergenceFailed`,
`Numerical`), модели (`ModelError`) и извлечение признаков (`NoPitchDetected`,
`InsufficientData { needed, got }`). `Result<T>` — алиас на этот тип.
Проверки зависят от функции: центрирование может позволить обработать сигнал
короче кадра. Не следует считать все низкоуровневые функции одинаково
защищёнными от неверных размеров и нулевых параметров.

## 2. Оконные функции

Источник: [`dsp/windows.rs`](../../sonara/src/dsp/windows.rs). Замена
`scipy.signal.get_window` для подмножества, нужного аудио-анализу.

**Обобщённое косинусное окно.** Hann, Hamming и Blackman — частные случаи одной
функции `general_cosine`:

```
w[i] = Σ_k (-1)^k · a_k · cos(2π · k · i / M),   i = 0..n-1
```

где `M = n` для периодического окна (`fftbins = true`, для FFT) и `M = n - 1`
для симметричного (`fftbins = false`, для проектирования фильтров).
Коэффициенты: Hann `[0.5, 0.5]`, Hamming `[0.54, 0.46]`, Blackman
`[0.42, 0.50, 0.08]`.

**Остальные окна:**

- `bartlett` — треугольник `2x` при `x ≤ 0.5`, иначе `2 - 2x`, `x = i/M`.
- `boxcar` — единицы; параметра `fftbins` нет.
- `kaiser(n, beta)` — `I₀(β·√(1-α²)) / I₀(β)`, `α = 2i/M - 1`. Модифицированная
  функция Бесселя `I₀` считается рядом до 50 членов с ранним выходом при
  относительном вкладе `< 1e-16`. При `β = 0` окно вырождается в прямоугольное.
- `tukey(n, alpha)` — косинусные скаты шириной `alpha/2` с каждой стороны,
  плато посередине; `alpha` зажимается в `[0, 1]`, `alpha = 0` даёт прямоугольник.
- `gaussian(n, std)` — `exp(-0.5·x²)`, где `x = (i - M/2) / (std · M/2)`.
  **Расхождение:** в SciPy `std` задаётся в отсчётах, здесь — в долях
  полудлины окна. `std = 0.4` означает σ = 0.4·M/2, а не 0.4 отсчёта.

**Значения по умолчанию в `get_window`** (для `Named`): `kaiser` → β = 14,
`tukey` → α = 0.5, `gaussian` → std = 0.4. Синонимы: `hanning`, `triangular`,
`triang`, `rectangular`, `ones`. `WindowSpec::Array` принимается только при
точном совпадении длины (`ShapeMismatch` иначе). Окна длины 0 и 1 возвращают
пустой массив и `[1.0]` соответственно.

## 3. IIR-фильтрация и экстремумы

Источник: [`dsp/iir.rs`](../../sonara/src/dsp/iir.rs),
[`dsp/extrema.rs`](../../sonara/src/dsp/extrema.rs).

**`lfilter(b, a, x)`** — прямая форма II транспонированная, совместимая с
`scipy.signal.lfilter`. Коэффициенты нормируются на `a[0]` (ошибка при
`a[0] = 0` или пустых массивах). Состояние — вектор длиной
`max(len(b), len(a))`; на каждом отсчёте:

```
y[i]      = b[0]·x[i] + s[0]
s[j]      = b[j+1]·x[i] - a[j+1]·y[i] + s[j+1]
```

Нулевые начальные условия. Используется для pre/de-emphasis
([§15](#15-эффекты)).

**`filtfilt(b, a, x)`** — фильтрация вперёд-назад для нулевой фазы. Требует
`n ≥ 3`. Края дополняются нечётным отражением на `3·max(len(a), len(b))`
отсчётов (но не больше `n - 1`): слева `2·x[0] - x[i+1]`, справа
`2·x[n-1] - x[n-2-i]`. **Приближение:** SciPy дополнительно подбирает начальное
состояние фильтра (`lfilter_zi`), чтобы исключить переходный процесс; здесь
функция `lfilter_zi` присутствует в файле, но помечена `dead_code` и не
вызывается. Переходные артефакты гасятся только отражением.

**`sosfiltfilt(sos, x)`** — каскад биквадов `[b0, b1, b2, a0, a1, a2]`.
**Приближение:** каждая секция прогоняется через отдельный `filtfilt` (со своим
дополнением краёв), а не через один общий проход, как в SciPy. Результат
эквивалентен по частотной характеристике, но краевые эффекты накапливаются
по секциям.

**`argrelmax` / `argrelmin(x, order)`** — строгие локальные экстремумы: `x[i]`
должен быть строго больше (меньше) всех соседей на расстоянии `1..=order` с
обеих сторон. Плато не считаются экстремумами. Кандидаты берутся только из
диапазона `order..n-order`.

## 4. FFT и кэш планов

Источник: [`core/fft.rs`](../../sonara/src/core/fft.rs). Обёртка над крейтом
`realfft`.

**Кэш.** Планы FFT хранятся в `thread_local!` `RefCell<FftCache>` — по одному
на поток, без мьютексов. Кэш помнит только **последний** прямой и последний
обратный план по размеру `n`; при смене размера план запрашивается у
`RealFftPlanner` заново (у которого есть свой внутренний `HashMap`). Один
scratch-буфер разделяется обоими направлениями и растёт до максимума
требуемого. Повторные FFT одного размера переиспользуют план и scratch,
но весь STFT всё равно выделяет память под результат и рабочие массивы.

**Функции:**

- `rfft(input, output)` — вещественный вход длины `n`, выход строго
  `n/2 + 1` комплексных бинов (`ShapeMismatch` иначе). Вход **изменяется**
  (`realfft` использует его как рабочий буфер).
- `irfft(input, output)` — обратное преобразование **без нормировки**: результат
  умножен на `n`. Вызывающий код делит сам.
- `rfft_alloc` / `irfft_alloc` — аллоцирующие варианты; `irfft_alloc`
  применяет `1/n`.
- `max_columns_in_block(n_fft)` — сколько столбцов спектра помещается в
  `MAX_MEM_BLOCK = 256 KiB` (`(n_fft/2+1) · 8` байт на столбец). Экспортируется
  как ориентир для блочной обработки; в самом STFT сейчас не используется.

## 5. STFT, ISTFT и спектральные операции

Источник: [`core/spectrum.rs`](../../sonara/src/core/spectrum.rs). Самый
загруженный файл ядра: `stft` — точка с наибольшим fan-out в крейте.

### 5.1. `stft`

Сигнатура: `stft(y, n_fft, hop_length, win_length, window, center, pad_mode)`.

Значения по умолчанию: `win_length = n_fft`, `hop_length = win_length / 4`.
Окно генерируется как периодическое (`fftbins = true`) длиной `win_length` и
дополняется нулями по центру до `n_fft`.

Дополнение при `center = true` — по `n_fft / 2` с каждой стороны:

| `PadMode` | Реализация |
| --- | --- |
| `Constant` | нули |
| `Reflect` | зеркало без повторения краевого отсчёта (`y[1], y[2], …`) |
| `Edge` | повтор краевого отсчёта |
| `Symmetric`, `LinearRamp` | **Приближение:** молча заменяются на нули |

Число кадров и бинов:

```
n_frames = 1 + (len(y_padded) - n_fft) / hop_length
n_bins   = 1 + n_fft / 2
```

Если сигнал после дополнения короче `n_fft` — `InsufficientData`. Перед
работой вызывается `valid_audio` (пустой или не-конечный сигнал → `InvalidAudio`).

**Параллелизм.** При `n_frames ≥ 32` (`PARALLEL_THRESHOLD`) кадры считаются
через `rayon` в плоский буфер и затем копируются в матрицу; при меньшем числе
кадров — последовательно с одной парой буферов. В параллельной ветви каждый
кадр аллоцирует свои буферы, а `rfft_alloc` при ошибке паникует (`expect`).

Нормировки нет: `|X[k]|` для синуса единичной амплитуды с окном Hann равно
примерно `n_fft / 4`, как в librosa.

### 5.2. `stft_power` и `spectrogram`

`stft_power(y, n_fft, hop, window, center, _pad_mode, power)` — слитный путь
«STFT → `|X|^power`» без промежуточной комплексной матрицы. При `power = 2`
используется `norm_sqr()` (без `sqrt`), при `power = 1` — `norm()`, иначе
`norm().powf(power)`. **Приближение:** параметр `pad_mode` игнорируется, всегда
нули; `win_length` всегда равен `n_fft`.

`spectrogram(y, S, …)` — диспетчер: при готовом `S` применяет степень к
модулю, при `y` вызывает `stft_power`. Возвращает `(spec, n_fft)`.

### 5.3. `istft`

Восстанавливает сигнал перекрытием-сложением. `n_fft` выводится из числа
строк: `n_fft = 2·(n_bins - 1)`. Каждый кадр после `irfft` умножается на
`1/n_fft` и на окно; затем:

```
y[t]    = Σ_frames frame[t - offset] · w[t - offset]
y[t]   /= Σ_frames w²[t - offset]     (только там, где сумма > tiny)
```

Ожидаемая длина `n_fft + hop·(n_frames - 1)`; при `center = true` срезаются
`n_fft/2` с обеих сторон; `length` обрезает (но не дополняет) результат.

### 5.4. Магнитуда, фаза, децибелы

- `magphase(D, power)` → `(|D|^power, D/|D|)`; нулевые бины получают фазу `1+0i`.
- `power_to_db(S, ref, amin, top_db)`:
  `10·log10(max(S, amin)) - 10·log10(max(ref, amin))`, затем при `top_db`
  срез снизу на `max_db - top_db`. Значения по умолчанию задаёт вызывающий код
  (в `mfcc`: `ref = 1`, `amin = 1e-10`, `top_db = 80`).
- `amplitude_to_db` — `20·log10(max(S, amin)) − 20·log10(max(ref, amin))`
  с аналогичным ограничением `top_db`.
- `db_to_power`, `db_to_amplitude`, `power_to_db_1d` — обратные и 1-D варианты.
- `perceptual_weighting(S, freqs, kind)` — **прибавляет** к каждому столбцу
  кривую взвешивания в дБ ([§7](#7-единицы-измерения-и-шкалы)). Вход должен
  быть уже в дБ; сама функция его не логарифмирует.

### 5.5. Фазовый вокодер

`phase_vocoder(D, rate, hop)`: `rate > 1` ускоряет. Число выходных шагов
`n_steps = ceil((n_frames - 1) / rate) + 1`. Ожидаемый набег фазы на бин
`Δφ_k = 2π · k · hop / n_fft`. На каждом шаге: позиция `t = step·rate`,
магнитуда интерполируется линейно между кадрами `⌊t⌋` и `⌊t⌋+1`, фаза
накапливается как `φ += Δφ_k + wrap(φ_{t+1} - φ_t - Δφ_k)` с обёрткой в
`[-π, π]`. Начальная фаза — фаза первого кадра. Последний неполный шаг
копирует магнитуду без интерполяции.

### 5.6. Griffin-Lim

`griffinlim(S_mag, n_iter, hop, win_length, window)`: случайная начальная фаза
из детерминированного xorshift64 с seed 42 (результат воспроизводим), DC и
Найквист принудительно вещественные. Цикл `n_iter` раз: `istft → stft →`
заменить модуль на целевой, сохранить фазу. Число столбцов после `stft`
может отличаться — берётся минимум. **Приближение:** без momentum
(`momentum = 0` в терминах librosa) и без случайного выбора seed.

### 5.7. PCEN

`pcen(S, sr, hop, gain, bias, power, time_constant, eps)`:

```
T      = time_constant · sr / hop            (в кадрах)
s      = exp(-1 / T)
M[t]   = s · M[t-1] + (1 - s) · S[t],   M[0] = S[0]
pcen   = (S / (eps + M)^gain + bias)^power - bias^power
```

**Приближение:** в librosa коэффициент сглаживания выводится через
`(sqrt(1 + 4T²) - 1) / (2T²)`; здесь используется простое `exp(-1/T)`. Значения
по умолчанию задаёт вызывающий код.

### 5.8. `iirt`, `reassigned_spectrogram`, `fmt`

- **`iirt` — Расхождение.** Docstring обещает банк биквадных IIR-фильтров на
  логарифмической сетке. Реальный код вычисляет для каждого кадра среднюю
  энергию `Σ x² / len` по **нефильтрованному** сигналу и записывает одно и то
  же значение во все `n_filters` строк. Сетка частот (`cqt_frequencies` с
  12 бинами на октаву) и полоса (четверть тона) считаются, но не используются.
  Выход имеет форму `(n_filters, n_frames)`, но частотной информации не несёт.
- **`reassigned_spectrogram` — Расхождение.** Возвращает обычный power-спектр
  (`stft_power` с Hann). Переназначения по времени и частоте нет; комментарий
  в коде это признаёт.
- **`fmt` (Fast Mellin Transform).** Логарифмическая передискретизация
  `t_i = t_min · exp((i/n_out) · ln(n / t_min))` с линейной интерполяцией
  между соседними отсчётами, затем `|rfft|`. **Приближение:** нет
  компенсирующего множителя `t^(-β)` и без выбора `kind`; это масштабно-
  инвариантное «по духу», но не эквивалент `librosa.fmt`.

## 6. Декодирование, ресемплинг, синтез

Источник: [`core/audio.rs`](../../sonara/src/core/audio.rs).

### 6.1. Загрузка

`load(path, sr, mono, offset, duration)` → `(y, sr)`; `load_with_tags(…,
want_tags)` дополнительно возвращает `Option<TrackTags>`.

Маршрут декодирования:

1. Расширение `.wav` → сначала **Hound** (быстрый путь; int-семплы масштабируются
   на `1 / 2^(bits-1)`, float берутся как есть). Если Hound отказал — повтор
   через **Symphonia 0.6**; при двойном отказе обе диагностики склеиваются в
   одну ошибку, а категория (`AudioFile`/`UnsupportedFormat`/`Decode`)
   сохраняется, если обе стороны согласны. WAV никогда не отдаёт теги.
2. Всё остальное → Symphonia. Если теги не запрошены, регистрируются только
   контейнерные ридеры (ADTS, CAF, FLAC, MP4, MPA, AIFF, WAV, OGG, MKV) без
   metadata-ридеров — это экономит лишний проход по хвосту файла. Для `.mp3`
   при провале общего probe делается повторная попытка напрямую через
   `MpaReader`, который ресинхронизируется на MPEG-кадры (лечит битые ID3 и
   мусор перед первым кадром).
3. Пакетная терпимость: `DecodeError` от кодека пропускает пакет и продолжает,
   `ResetRequired` пересоздаёт декодер. После цикла — защита: если пропуски были,
   а семплов нет или есть не-конечные — ошибка.

Затем `offset`/`duration` применяются в **нативных** отсчётах (offset за
пределами файла → `InvalidParameter`), многоканальный поток деинтерливится в
`(n_channels, n_samples)`, при `mono = true` усредняется (`to_mono` =
`mean_axis(0)`), иначе **берётся только первый канал** (многоканальный возврат
не реализован). Ресемплинг делается в самом конце, если `sr ≠ 0` и `sr ≠ native`.

**Теги.** Symphonia ставит ревизии метаданных в очередь старейшая-первой; код
проходит их **с конца** (новейшая — например ведущий ID3v2 — приоритетнее
хвостового ID3v1), а старшие ревизии заполняют только пустые поля. `year` —
первые 4 цифры `Date`/`ReleaseDate`; `original_year` — из `OriginalDate`-тегов
или сырых ключей `TORY`/`TDOR`/`ORIGINALYEAR`/`TXXX:originalyear`, без отката
на `year`.

`get_duration` для WAV читает заголовок; для остальных форматов **декодирует
весь файл** (дорого на больших файлах). `get_samplerate` аналогично.

### 6.2. Ресемплинг

`resample(y, orig_sr, target_sr)`:

- равные частоты → копия;
- `orig_sr == 2·target_sr` → `decimate_half`: 31-отводный полуполосный FIR
  (взвешенный Хэммингом `sinc`), центральный коэффициент 0.5, ненулевые
  отводы только на нечётных смещениях ±1…±15, нормировка на единичное усиление
  по DC. Восемь MAC-операций на выходной отсчёт; края дополняются нулями.
  **Приближение:** 31 отвод даёт умеренное подавление в переходной полосе —
  это не «идеальный» антиалиасинг, а компромисс ради скорости (комментарий в
  коде: ~20× быстрее sinc-ресемплинга);
- иначе → `rubato::Fft` с `chunk_size = 1024`, `FixedSync::Input`, одно
  sub-chunk, моно; весь сигнал обрабатывается разом через
  `process_all_into_buffer`.

`StreamResampler` — тот же `rubato::Fft`, но с внутренним буфером: `process_chunk`
копит входы до `input_frames_next()` и прогоняет столько полных блоков, сколько
накопилось; `flush` дополняет хвост нулями до полного блока. `stream_with_resample`
загружает файл в нативной частоте, режет на блоки по `block_length · hop_length`
нативных отсчётов (масштабированных на отношение частот) и ресемплирует поблочно.
`stream` (без ресемплинга) просто загружает файл целиком и режет на блоки длиной
`block_length·hop_length + frame_length` с шагом `block_length·hop_length` —
это не потоковое чтение, а нарезка уже загруженного буфера.

### 6.3. Временные функции

- `autocorrelate(y, max_size)` — через FFT: `ifft(|fft(x)|²)` с дополнением
  нулями до `next_pow2(2n)`, деление на размер FFT. Возвращает первые
  `min(max_size, n)` лагов. Нормировки на `acf[0]` нет.
- `lpc(y, order)` — **Расхождение:** docstring говорит «метод Бурга», реализация
  — рекурсия Левинсона-Дурбина по автокорреляции (`order + 1` лагов). Выход
  `order + 1` коэффициентов, `a[0] = 1`. Ранний выход при ошибке предсказания
  `< 1e-30`; нулевой сигнал даёт `[1, 0, …]`.
- `zero_crossings(y, threshold)` — отсчёты с `|y| ≤ threshold` считаются нулём,
  пересечение — смена знака между соседями; `true` ставится на второй отсчёт пары.
- `clicks(times, sr, length, click_freq, click_duration)` — синусоидальные
  щелчки без огибающей (**Приближение:** librosa применяет экспоненциальное
  затухание), суммируются в буфер длины `length`.
- `tone(f, sr, length)` — `sin(2π f i / sr)`.
- `chirp(fmin, fmax, sr, length)` — линейный свип: фаза
  `2π(fmin·t + (fmax - fmin)·t²/(2·duration))`. Только линейный режим.
- `mu_compress` / `mu_expand` — μ-закон: `sign(x)·ln(1 + μ|x|)/ln(1 + μ)` и
  обратное. Без квантования в целые.

## 7. Единицы измерения и шкалы

Источник: [`core/convert.rs`](../../sonara/src/core/convert.rs). Самая широкая
публичная поверхность в крейте, чистые функции без состояния.

**Константы.** `A4 = 440 Hz`, `A4_MIDI = 69` (приватные; переопределяются
аргументом `a4_freq: Option<Float>` там, где он есть).

**Кадры ↔ отсчёты ↔ время.** `frames_to_time = frame · hop / sr`,
`time_to_frames = floor(t · sr / hop)`, `time_to_samples = round(t · sr)`,
`samples_to_frames = floor(s / hop)`. Блоки: `blocks_to_frames = b · block_length / hop`.
Любая структура, хранящая индексы кадров, обязана хранить рядом `hop` и `sr`.

**Mel.** Две шкалы:

- Slaney (по умолчанию, `htk = false`): линейная ниже 1000 Hz
  (`f / (200/3)`), выше — `15 + ln(f/1000) / (ln(6.4)/27)`;
- HTK: `2595 · log10(1 + f/700)`.

`mel_frequencies(n_mels, fmin, fmax, htk)` — равномерная сетка в mel,
переведённая в Hz (при `n_mels = 1` возвращает `fmin`).

**MIDI и ноты.** `hz_to_midi = 69 + 12·log2(f / a4)` (NaN при `f ≤ 0`).
`midi_to_note` округляет и даёт диезную запись (`C#5`); `note_to_midi` парсит
буквы `A–G` (регистронезависимо), любое число `#`/`♯`/`b`/`♭` и целую октаву,
формула `12·(octave + 1) + base + offset`. `hz_to_octs` — октавы относительно
`A4_tuned / 16` (≈ 27.5 Hz при tuning 0), где
`A4_tuned = a4 · 2^(tuning / bins_per_octave)`. `a4_to_tuning`/`tuning_to_a4` —
обратные преобразования в долях бина.

**Сетки частот.** `fft_frequencies(sr, n_fft)` — `k · sr / n_fft`,
`k = 0..n_fft/2`. `cqt_frequencies(n_bins, fmin, bpo)` — `fmin · 2^(i/bpo)`.
`tempo_frequencies(n_bins, hop, sr)` — `60 · sr / (hop · lag)` (BPM по лагу;
лаг 0 → 0). `fourier_tempo_frequencies(sr, win, hop)` — `k · sr · 60 / (hop · win)`.

**Взвешивание A/B/C/D/Z.** Стандартные формулы IEC 61672 в дБ: A-кривая с
полюсами 20.6, 107.7, 737.9, 12194 Hz и смещением +2.0 дБ; B — 158.5 Hz и
+0.17; C — +0.06; D — по формуле с `h(f)`; Z — ноль. `frequency_weighting(freqs,
kind)` векторизует по строке `"A".."Z"`, `multi_frequency_weighting` складывает
несколько кривых в матрицу `(n_kinds, n_freqs)`.

**Svara и FJS.** `hz_to_svara_h/c` — 12 ступеней хиндустани/карнатик по
округлённому полутоновому смещению от `sa`; параметр `abbr` не используется.
`hz_to_fjs(freq, ref)` сворачивает отношение в `[1, 2)` и сравнивает с 12
чистыми интервалами с допуском 0.01; иначе печатает отношение с 4 знаками.
**Приближение:** это не настоящая FJS-нотация с простыми-множителями, а
таблица подстановки.

## 8. Constant-Q и Variable-Q

Источник: [`core/constantq.rs`](../../sonara/src/core/constantq.rs). Форма
результата `(n_bins, n_frames)`, комплексные значения.

### 8.1. Параметры

`cqt(y, sr, hop, fmin, n_bins, bins_per_octave, filter_scale)` — это `vqt` с
`gamma = 0`. `fmin` по умолчанию `32.7032 Hz` (C1). Определения:

```
α        = 2^(1/bpo) - 1                     относительная ширина бина
Q        = filter_scale / α
len(f)   = Q · sr / f                        (gamma = 0)
len(f)   = Q · sr / (f + gamma / α)          (gamma > 0, VQT)
```

`n_octaves = ceil(n_bins / bpo)`.

### 8.2. Рекурсия по октавам

Октавы обрабатываются **сверху вниз**. Для каждой:

1. `cqt_response` строит частотный банк фильтров для бинов октавы
   (`build_cq_filterbank`) и берёт `stft` сигнала с **прямоугольным** окном
   (`"ones"`), `n_fft = next_pow2(max(max_len, 2·hop))`, `center = true`,
   нулевое дополнение. Затем `out[i, t] = Σ_f basis[i, f] · X[f, t]` — плотное
   матричное умножение по всем `n_fft/2 + 1` бинам (**Приближение:** librosa
   использует разреженный банк; здесь O(`n_bins · n_fft_bins`) на кадр).
2. Если это не последняя октава **и `hop` чётный** — сигнал прореживается
   «каждый второй отсчёт», `sr /= 2`, `hop /= 2`.
   **Приближение:** прореживание без антиалиасингового фильтра (комментарий в
   коде это признаёт). Энергия выше новой частоты Найквиста заворачивается в
   нижние октавы. Если `hop` нечётный, прореживание прекращается, и все
   оставшиеся октавы считаются на прежней частоте с более длинным `n_fft`.
3. Результаты переворачиваются (низ → верх) и укладываются в матрицу; число
   кадров = минимум по октавам, лишние столбцы отбрасываются.

Пара `(sr, hop)` должна уменьшаться синхронно,
иначе временная сетка октав разъедется. Практический совет: выбирайте `hop`,
делящийся на `2^(n_octaves - 1)`.

### 8.3. Банк фильтров

Каждый фильтр — комплексная экспонента `exp(2πj f t)` длиной `ceil(len(f))`
отсчётов, взвешенная **симметричным** Hann и поделённая на `len(f)`,
центрированная в буфере `n_fft`. Его спектр считается двумя вещественными
FFT (по Re и Im) и складывается как `F(re) + j·F(im)`. **Приближение:**
берётся только половина спектра `0..n_fft/2`, то есть фильтр обрезан по
отрицательным частотам — это допустимо для вещественного входа, но означает,
что `basis` не является полным спектром аналитического сигнала.

### 8.4. Варианты и обратное преобразование

- `pseudo_cqt` — **Расхождение с docstring:** заявлен «один FFT на все бины»,
  фактически возвращает `|cqt(...)|`, то есть полную рекурсию и модуль.
- `hybrid_cqt` — делегирует в `cqt` (комментарий: разделение по длине фильтра
  не реализовано).
- `icqt(cq, sr, hop, fmin, bpo, filter_scale)` — строит тот же банк на
  `n_fft = next_pow2(max(Q·sr/fmin, 2·hop))`, применяет **сопряжённо-
  транспонированную** матрицу (не псевдообратную: без учёта `(BᴴB)⁻¹`), DC и
  Найквист делает вещественными и восстанавливает через `istft` с Hann и
  `hop`. Амплитуда результата не калибрована.
- `griffinlim_cqt` — Griffin-Lim поверх `icqt`/`cqt` с `filter_scale = 1`,
  xorshift64 seed 42.

## 9. Оценка высоты тона

Источник: [`core/pitch.rs`](../../sonara/src/core/pitch.rs).

### 9.1. YIN

`yin(y, fmin, fmax, sr, frame_length, hop, trough_threshold)`, `hop` по
умолчанию `frame_length / 4`. Ограничения лагов:

```
τ_min = floor(sr / fmax),   τ_max = ceil(sr / fmin),   требуется τ_max < frame_length
```

Кадры нарезаются `utils::frame` **без центрирования** (кадр `t` начинается с
`t·hop`; результат сдвинут на полкадра относительно STFT-признаков). Для
каждого кадра считается CMNDF (кумулятивно нормированная разностная функция):

```
d[τ]      = Σ_{j=0}^{N-τ-1} (x[j] - x[j+τ])²           (во временной области, O(N·τ_max))
d'[0]     = 1
d'[τ]     = d[τ] · τ / Σ_{k=1}^{τ} d[k]
```

Выбор: **первый** локальный минимум на `[τ_min, τ_max]` со значением ниже
`trough_threshold`; лаг уточняется параболической интерполяцией по трём
точкам; `f0 = sr / τ_refined`. Если такого минимума нет, берётся глобальный
минимум, но только если он `< 1.0`. Невокализованные кадры — `NaN`.

**Приближение:** разностная функция считается «в лоб», а не через FFT, как
в librosa; на длинных кадрах это медленнее, но численно проще.

### 9.2. pYIN

`pyin(y, fmin, fmax, sr, frame_length, hop)` → `(f0, voiced_flag, voiced_prob)`.
Параметры зашиты в код:

| Параметр | Значение |
| --- | --- |
| число порогов | 100, сетка `0.00..1.00` |
| prior порогов | Beta(2, 18) (регуляризованная неполная бета-функция через цепную дробь, `ln Γ` по Ланцошу) |
| Boltzmann | λ = 2 (ранний минимум предпочтительнее) |
| разрешение | 0.1 полутона → 10 бинов на полутон |
| `max_transition_rate` | 35.92 октав/с |
| `switch_prob` | 0.01 (voiced ↔ unvoiced) |
| `no_trough_prob` | 0.01 |

Алгоритм: сигнал центрируется нулями на `frame_length/2`, кадрируется; для
каждого кадра берётся CMNDF на лагах `0..max_period` и находятся **все**
локальные минимумы. Для каждого порога `θ_k` минимумы ниже порога получают вес
`Boltzmann(pos) · P_beta(θ_k)`, где `pos` — порядковый номер минимума среди
прошедших порог. Глобальный минимум дополнительно получает
`no_trough_prob · Σ P_beta` по порогам, которые он не прошёл. Вероятность
каждого минимума переводится в частоту, квантуется в бин
`round(12 · 10 · log2(f0 / fmin))` и суммируется в матрицу наблюдений
`(2·n_bins, n_frames)`: верхняя половина — voiced, нижняя — unvoiced с
равномерным `(1 - Σ voiced) / n_bins`.

Переходная матрица — произведение Кронекера `transition_loop(2, 1 - switch)` ⊗
`transition_local(n_bins, width)`, `width = round(35.92 · 12 · hop / sr) · 10 + 1`.
Декодирование — `sequence::viterbi` в лог-пространстве с равномерным
начальным распределением. Состояние `< n_bins` → voiced, частота
`fmin · 2^(s / 120)`.

**Расхождение (существенное).** При переводе минимума в период код делает
`period = min_period + refined`, где `refined` — **уже абсолютный лаг** в
CMNDF (она считается с лага 0). В librosa CMNDF вычисляется начиная с
`min_period`, и сложение там корректно; здесь оно смещает период на
`floor(sr/fmax)` отсчётов и **занижает f0** (для `fmax = 2000`, `sr = 22050`
смещение 11 отсчётов: 440 Hz → около 358 Hz). Юнит-тест `test_pyin_pure_tone`
этого не ловит — его условие
`close_to_440 > 0 || valid_f0.len() > 0` истинно при любом непустом
результате. Это вывод из индексации в исходниках, а не замер точности на
корпусе. Для абсолютной высоты проверяйте `yin` и `pyin` на контрольных тонах;
ни один из них не гарантирует точность на произвольной полифонической записи.

Второе, менее критичное: `voiced_prob` — это сумма весов минимумов, зажатая
в `[0, 1]`, а не апостериорная вероятность после Viterbi.

### 9.3. Тюнинг и `piptrack`

- `piptrack(y, sr, n_fft, hop)` → `(pitches, magnitudes)`, обе `(n_bins,
  n_frames)`. STFT с Hann, для каждого локального максимума модуля по частоте
  — параболическая интерполяция **в логарифме** магнитуды:
  `δ = (ln a - ln c) / (2·(2·ln b - ln a - ln c))`, `f = f_k + δ · sr / n_fft`.
  Порогов по амплитуде нет (**Приближение:** librosa отбрасывает пики ниже
  `threshold · max`); `fmin`/`fmax` не поддерживаются.
- `pitch_tuning(pitches, resolution, bpo)` — переводит в MIDI, берёт дробную
  часть бина `midi · bpo / 12`, возвращает **медиану** остатков в долях
  полутона. **Приближение:** librosa строит гистограмму с шагом `resolution`
  и берёт её моду; здесь `resolution` не используется.
- `estimate_tuning(y, sr, n_fft, resolution, bpo)` — `piptrack` → все ненулевые
  частоты без взвешивания по магнитуде → `pitch_tuning`. Без сигнала возвращает 0.

## 10. Гармонический анализ

Источник: [`core/harmonic.rs`](../../sonara/src/core/harmonic.rs).

- `salience(S, freqs, harmonics, weights, _fill)` — для каждого бина `i` и
  гармоники `h` находит **ближайший** бин к `freqs[i]·h` (линейный поиск по
  всем бинам, O(`n_bins²·n_harm·n_frames`)) и суммирует `w_h · S[bin, t]`.
  **Приближение:** без интерполяции и без опции `filter_peaks`; `fill_value`
  не используется. На больших `n_fft` это заметно медленно.
- `interp_harmonics(S, freqs, harmonics, fill)` — линейная интерполяция между
  соседними бинами для каждой гармоники; выход **сплющен** в
  `(n_harm · n_bins, n_frames)`, блок `h` занимает строки `h·n_bins..`. Бины,
  для которых цель выше `freqs[last]`, остаются `fill_value`.
- `f0_harmonics(S, freqs, f0, harmonics, fill)` — то же для траектории `f0`
  (`NaN`/`≤ 0` пропускаются), выход `(n_harm, n_frames)`. Требует
  `len(f0) == n_frames`.

Поиск нижнего бина — линейный проход по всем `freqs` (без бинарного поиска).

## 11. Нотация и интервалы

Источник: [`core/notation.rs`](../../sonara/src/core/notation.rs),
[`core/intervals.rs`](../../sonara/src/core/intervals.rs). Это чистые
таблицы, без сигналов.

**Тональности.** `key_to_notes("Eb:maj")` — формат строго `нота:лад`, лады
`maj`/`major`/`min`/`minor` (только натуральный минор). Бемоли выбираются, если
тоника содержит `b` или входит в `{F, Bb, Eb, Ab, Db, Gb}`. `key_to_degrees`
возвращает ступени `[0,2,4,5,7,9,11]` или `[0,2,3,5,7,8,10]`.

**Мелакарта и тхаат.** `mela_to_degrees(1..72)` вычисляет ступени
комбинаторно: чакра `= (mela-1)/6` задаёт Ma (`5` для чакр 0–5, `6` для 6–11)
и пару Ri/Ga (6 вариантов), индекс внутри чакры — пару Da/Ni (6 вариантов).
`mela_to_svara` даёт имена `Sa, Ri1..Ni2`. Десять тхаатов — явная таблица
ступеней. `list_mela`, `list_thaat` — списки имён.

**Квинтовый круг и FJS.** `fifths_to_note(k)` — `NOTE_NAMES[(7k) mod 12]`
(только диезная запись). `interval_to_fjs` — таблица из 7 чистых интервалов с
допуском 0.01, иначе число. **Приближение:** не FJS.

**Интервалы.** `pythagorean_intervals(bpo)` — `(3/2)^k` для `k` от
`-bpo/2..bpo/2`, свёрнутые в октаву и отсортированные. `plimit_intervals(p,
bpo)` — перебор `p_i^a` для первых **не более трёх** простых до `p` со
степенями `-6..6`, свёртка в октаву, дедупликация по `round(r · 1e10)`,
сортировка и **усечение до `bpo` наименьших** отношений. **Приближение:**
librosa выбирает `bpo` интервалов по минимальной высоте (Tenney height),
здесь берутся просто самые низкие по значению — набор получается другим.
`interval_frequencies(n_bins, fmin, intervals, bpo)` раскладывает интервалы по
октавам: `fmin · 2^octave · intervals[degree]`.

## 12. Банки фильтров

Источник: [`filters.rs`](../../sonara/src/filters.rs). Все матрицы — `(n_filters, 1 + n_fft/2)`.

**`mel(sr, n_fft, n_mels, fmin, fmax, htk, norm)`.** `fmax ≤ 0` означает `sr/2`.
Строятся `n_mels + 2` равноотстоящих точек в mel, переводятся в Hz; фильтр `i`
— треугольник с вершиной в точке `i+1`:

```
w = (f - f_left) / (f_center - f_left)      при f_left ≤ f ≤ f_center
w = (f_right - f) / (f_right - f_center)    при f_center < f ≤ f_right
```

При `norm = "slaney"` строка умножается на `2 / (f_right - f_left)`
(единичная площадь). Треугольники строятся **по частотам FFT-бинов**, а не
по дробным индексам — совпадает с librosa.

**`chroma(sr, n_fft, n_chroma, tuning)`.** Порт `librosa.filters.chroma`
0.10 с мягким назначением. Для бина `j` позиция в хроматических единицах
`frqbins[j] = n_chroma · hz_to_octs(f_j, tuning, n_chroma)`; ширина бина
`binwidth = max(frqbins[j+1] - frqbins[j], 1)`. Вес класса `c`:

```
d      = wrap(frqbins[j] - (c + roll), (-n/2, n/2]),   roll = 3·(n_chroma/12)  (строка 0 = C)
w[c,j] = exp(-0.5 · (2d / binwidth)²)
```

Столбцы нормируются на сумму 1, DC остаётся нулём. Затем октавное взвешивание
Гауссом с центром `ctroct = 5.0` (≈ 880 Hz) и шириной `octwidth = 2.0`,
подавляющее широкополосную энергию на высоких `sr`. Комментарий в коде
объясняет мотив: без ширины бина басовые бины при 44.1 kHz покрывают около
2.7 полутонов и должны питать все накрытые классы.

**Constant-Q.** `constant_q_lengths(sr, fmin, n_bins, bpo, filter_scale,
window)` — `Q · sr / (f · bw)`, где `bw` — табличная полоса окна
(Hann 1.5018, Hamming 1.3629, Blackman 1.7268, Kaiser 1.7029 и т. д.; неизвестное
имя → Hann). `wavelet_lengths` — `filter_scale · sr / (f · bw)`.
**Расхождение:** `constantq.rs` эту функцию **не использует** — там длина
`Q · sr / f` без деления на полосу окна.

**Прочее.** `window_sumsquare` — сумма квадратов окна по кадрам (проверка
COLA). `cq_to_chroma(n_input, _bpo, n_chroma, _fmin)` — **Приближение:**
жёсткое отображение `i mod n_chroma`, без учёта `bins_per_octave` и `fmin`;
корректно только при `bpo = n_chroma` и `fmin` на C. `mr_frequencies` — 84
CQT-частоты от `A4_tuned · 2^-4.75` и эвристические частоты дискретизации
`max(8f, 1000)`. `diagonal_filter(n, width)` — ленточная матрица с `1/width`.
`semitone_filterbank` — треугольники ±четверть тона вокруг `cqt_frequencies`.

## 13. Спектральные признаки

Источник: [`feature/spectral.rs`](../../sonara/src/feature/spectral.rs),
[`feature/inverse.rs`](../../sonara/src/feature/inverse.rs). Многие спектральные
экстракторы принимают либо `y`, либо готовый `S`; некоторые функции принимают
только сигнал или только матрицу. Типичный спектральный путь использует Hann,
центрирование и нулевое дополнение. Формы и исключения указаны ниже.

> `analyze.rs` эти функции **не вызывает**: там инлайнен эквивалентный слитный
> проход, чтобы один STFT питал mel/chroma/MFCC/contrast/HPCP. Правка здесь,
> не отражённая там, приводит к расхождению между модульным API и
> `TrackAnalysis`.

- **`melspectrogram(y, S, sr, n_fft, hop, n_mels, fmin, fmax, power)`** —
  при `S`: `mel_fb · S` (BLAS `dot`). При `y`: слитный проход — для каждого кадра
  FFT → `|X|^power` → **разреженная** проекция: для каждой mel-строки хранятся
  только `(start_bin, ненулевые веса)`, что убирает около 97 % умножений.
  Последовательно (не `rayon`) ради локальности кэша. Банк — Slaney,
  `htk = false`.
- **`mfcc(y, S_mel, sr, n_mfcc, n_fft, hop, n_mels, fmin, fmax)`** —
  при входе `y`: `power_to_db(mel, ref=1, amin=1e-10, top_db=80)`;
  готовый `S_mel` уже должен быть в dB. Далее ортонормированная DCT-II:
  `D[k,n] = cos(π k (2n+1) / 2N) · √(1/N)` при `k = 0`, иначе `· √(2/N)`.
  `n_mfcc` усекается до `n_mels`.
- **`chroma_stft(y, S_power, sr, n_fft, hop, n_chroma, tuning)`** — power-спектр
  (`power = 2`) × банк из [§12](#12-банки-фильтров), затем L∞-нормировка каждого
  столбца (максимум = 1). Нормировка не выбирается.
- **`tonnetz(y, sr, n_fft, hop)`** — `chroma_stft` с 12 классами и `tuning = 0`,
  столбец нормируется на сумму 1, проекция на 6 осей: квинты (`7c`), малые
  терции (`3c`), большие терции (`4c`) через `sin`/`cos` от `2π·k·c/12`.
  **Приближение:** librosa использует радиусы 1, 1, 0.5 для трёх кругов;
  здесь все радиусы равны 1, и нет опции `chroma` на вход.
- **`spectral_centroid`** — `Σ f·S / Σ S` по magnitude (`power = 1`); 0 при
  нулевой сумме.
- **`spectral_bandwidth(…, p)`** — `(Σ S·|f - c|^p / Σ S)^(1/p)`.
- **`spectral_rolloff(…, roll_percent)`** — первая частота, где кумулятивная
  сумма `≥ roll_percent · total`. При `roll_percent` близком к 1 и пустой
  колонке остаётся 0.
- **`spectral_flatness(…, amin, power)`** — `exp(mean ln max(S, amin)) /
  mean S` по power-спектру.
- **`spectral_contrast(…, n_bands, fmin, quantile)`** — границы полос
  логарифмически от `fmin` до `sr/2`: `fmin · (fmax/fmin)^(i/n_bands)`.
  **Приближение:** librosa строит полосы октавами (`fmin · 2^i`) и добавляет
  полосу `0..fmin`; здесь полос ровно `n_bands`, а строка `n_bands` (последняя)
  — `log10(mean S)` всего кадра, а не контраст полосы. Внутри полосы: сортировка,
  `valley = S[⌊n·q⌋]`, `peak = S[n-1-⌊n·q⌋]`, контраст `log10 peak - log10 valley`
  (не среднее по квантилю, а одно значение).
- **`rms(y, S, frame_length, hop)`** — при `y`: центрирование нулями и прямой
  расчёт `√(Σ x² / frame_length)` без выделения матрицы кадров; при `S`:
  `√(mean S по частоте)` (**Приближение:** без учёта удвоения не-DC бинов и
  без деления на `n_fft`, как делает librosa).
- **`zero_crossing_rate(y, frame_length, hop)`** — кадры без центрирования,
  пересечения `/ frame_length`.
- **`poly_features(S, sr, n_fft, order)`** — **Расхождение:** docstring обещает
  МНК-аппроксимацию полиномом; фактически возвращает моменты
  `mean(S · f^k)` для `k = 0..order`. Это не коэффициенты полинома.

**Обратные преобразования** (`feature/inverse.rs`):

- `mel_to_stft(M, sr, n_fft, power)` — **Приближение:** задача неотрицательных
  наименьших квадратов `F X ≈ M` решается за фиксированные
  50 итераций проецированного градиентного спуска с шагом 0.01 из нулевой
  инициализации, затем `x^(1/power)`. Сходимость не проверяется, шаг не
  адаптивен — на больших амплитудах результат может быть далёк от оптимума.
- `mel_to_audio` — `mel_to_stft(power = 2)` → `griffinlim` с Hann.
- `mfcc_to_mel(mfcc, n_mels)` — обратная DCT-II по имеющимся коэффициентам
  (остальные считаются нулями), затем `10^(v/10)` (обратно к `power_to_db` с
  `ref = 1`; смещение `top_db` не восстанавливается).
- `mfcc_to_audio` — цепочка двух предыдущих.

Обратные функции принимают покадровые матрицы, а не `mfcc_mean`:
усреднённый вектор не содержит временной структуры. Они не экспортированы
в Python-привязке этой версии. Потерянная фаза и усечённые MFCC не допускают
однозначного восстановления исходной записи.

## 14. Разложение: HPSS, NMF, NN-фильтр

Источник: [`decompose.rs`](../../sonara/src/decompose.rs). Работает на
вещественных спектрограммах.

**`hpss(S, kernel_size, margin, power)`.** Две медианные фильтрации одного и
того же `S`: по времени (окно `kernel_size` вдоль кадров) → гармоническая
оценка `H̃`, по частоте → перкуссивная `P̃`. Маски:

```
h = H̃^power · margin^power,   p = P̃^power · margin^power
harmonic = S · h / (h + p),   percussive = S · p / (h + p)
```

**Приближение:** `margin` один и тот же для обеих компонент и, поскольку он
входит множителем в числитель и знаменатель одинаково, при положительном
конечном множителе **сокращается** в точной арифметике; при нулевом множителе
результат зануляется. В librosa `margin` задаёт порог
`H̃ > margin_h · P̃`, отсекая остаток. Медианный фильтр — «наивный»: на каждый
элемент собирается и сортируется окно (`O(n·k log k)`), края усекаются (без
дополнения), медиана — элемент `len/2`. Один общий `kernel_size` для обеих осей.

**`decompose_nmf(V, n_components, n_iter)`.** Мультипликативные обновления
Ли-Сеунга по евклидовой норме:

```
H ← H ⊙ (WᵀV) / (WᵀWH + ε),   W ← W ⊙ (VHᵀ) / (WHHᵀ + ε),   ε = 1e-10
```

Инициализация xorshift64 (seed 42) в `[0.01, 0.11)` — детерминирована.
Возвращает `(W (n_bins, k), H (k, n_frames))`. Без нормировки столбцов `W`
и без критерия останова.

**`nn_filter(S, k, metric)`.** Для каждого кадра — расстояния до всех
остальных (`cosine` или евклидово), `k` ближайших усредняются вместе с самим
кадром (`k + 1` слагаемых). O(`n_frames² · n_bins`). **Приближение:** только
среднее, без `aggregate = median` и без рекуррентной матрицы на входе.

## 15. Эффекты

Источник: [`effects.rs`](../../sonara/src/effects.rs). Спектральные эффекты
HPSS/time-stretch работают через `stft`/`istft` с Hann, `n_fft = 2048`,
`hop = 512`; trim/split и pre/de-emphasis используют другие пути.

- **`hpss(y, kernel_size, margin)`** — STFT → модуль → `decompose::hpss(power = 2)`
  → фаза оригинала возвращается на маскированные модули → два `istft` с
  `length = len(y)`.
- **`harmonic` / `percussive`** — обёртки, считающие оба компонента и
  выбрасывающие один.
- **`time_stretch(y, rate)`** — STFT → `phase_vocoder` → принудительно
  вещественные DC/Найквист → `istft` с `length = round(len / rate)`.
- **`pitch_shift(y, sr, n_steps, bpo)`** — `rate = 2^(-n_steps / bpo)`,
  `time_stretch`, затем `resample(target_sr = sr·rate → sr)`. Через
  `rubato::Fft` при нецелом отношении. **Приближение:** `target_sr`
  усекается до целого `u32`, поэтому для мелких сдвигов (например 0.1 полутона)
  отношение частот квантуется и сдвиг неточен.
- **`trim(y, top_db, frame_length, hop)`** — порог
  `max(rms) · 10^(-top_db/20)`; первая и последняя рамки выше порога задают
  `[first·hop, (last+1)·hop)`. Возвращает `(срез, (start, end))`; тишина →
  пустой буфер.
- **`split`** — те же пороги, интервалы по переходам silent/non-silent в
  единицах отсчётов. `split_with_constraints(…, sr, min_silence, min_signal)`
  дополнительно склеивает промежутки короче `min_silence` и отбрасывает
  сегменты короче `min_signal` (оба в секундах).
- **`remix(y, intervals)`** — конкатенация срезов в заданном порядке; выход
  за пределы сигнала усекается.
- **`preemphasis(y, coef)`** — `lfilter([1, -coef], [1])`, то есть
  `y[n] - coef·y[n-1]`; **`deemphasis`** — `lfilter([1], [1, -coef])`.
  Нулевые начальные условия (librosa даёт опцию `zi`).
- **`melody_separate(y, sr, fmin, fmax, n_harmonics, n_fft, hop)`** —
  `pyin` с `frame_length = n_fft` → STFT → для каждого вокализованного кадра
  Гауссовы пики шириной `σ = 2 · sr/n_fft` Hz на гармониках `f0·h ≤ sr/2`
  (берётся максимум пиков) → маска `m ∈ [0, 1]` → `melody = X·m`,
  `accompaniment = X·(1-m)` → два `istft`. Число кадров `pyin` может быть
  меньше STFT — лишние кадры остаются без маски (полностью в аккомпанементе).
  Наследует смещение `f0` из [§9.2](#92-pyin).

## 16. Динамическое программирование: DTW, Viterbi, RQA

Источник: [`sequence.rs`](../../sonara/src/sequence.rs).

**`dtw(C, step_sizes)`.** Вход — матрица стоимости `(N, M)`; шаги по
умолчанию `[(1,1), (0,1), (1,0)]`, все с весом 1. Накопленная стоимость:

```
D[0,0] = C[0,0]
D[i,j] = C[i,j] + min_{(di,dj)} D[i-di, j-dj]
```

Затем `dtw_backtracking` от `(N-1, M-1)` к `(0, 0)` по минимальной
предшествующей стоимости. Возвращает `(D, path)` с путём в порядке возрастания.
**Приближение:** нет весов шагов, глобальных ограничений (Sakoe-Chiba, Itakura),
режима subsequence и `backtrack = false`; вход — только готовая матрица `C`,
а не пара последовательностей.

**`viterbi(log_prob, log_trans, log_init)`.** Стандартный Viterbi в
лог-пространстве: `trellis[s, 0] = init[s] + obs[s, 0]` (по умолчанию
равномерный `-ln n_states`), `trellis[j, t] = max_i(trellis[i, t-1] +
trans[i, j]) + obs[j, t]`, обратный проход по указателям. O(`n_states² ·
n_frames`). Форма `log_trans` проверяется. **Вход — уже логарифмы**, в отличие
от librosa, где принимаются вероятности.

- `viterbi_discriminative` — **Расхождение с docstring:** заявлены
  «дискриминативные» апостериорные вероятности с делением на prior; на деле
  вызывает обычный `viterbi` без изменений.
- `viterbi_binary` — требует ровно 2 строки, возвращает `states == 1` как `bool`.

**Переходные матрицы** (в вероятностях, не логарифмах):

- `transition_uniform(n)` — все `1/n`.
- `transition_loop(n, p)` — `p` на диагонали, `1 - p` на **следующее**
  состояние, последнее состояние поглощающее (`1.0`). **Приближение:** в
  librosa остаток `1 - p` распределяется на **все** остальные состояния,
  а не только на `i + 1`. При `n = 2` здесь получается `[[p, 1-p], [0, 1]]`,
  то есть переход из второго состояния обратно в первое невозможен.
  В pYIN это делает unvoiced-состояние поглощающим по отношению к voiced.
- `transition_cycle(n, p)` — как loop, но последнее переходит в первое.
- `transition_local(n, width)` — равномерно по полосе `[i - width/2, i + width/2]`,
  усечённой к краям; у краевых состояний полоса уже, и вероятности там выше.

**`rqa(sim)`** — **Приближение:** не полный RQA librosa (с штрафами
`gap_onset`/`gap_extend` и трекингом путей), а простой подсчёт длины
диагональных серий: `score[i,j] = score[i-1,j-1] + 1`, если `sim[i,j] > 0`.

## 17. Структурная сегментация

Источник: [`segment.rs`](../../sonara/src/segment.rs). Признаки — `(n_features, n_frames)`.

- **`recurrence_matrix(data, k, metric, sym)`** — полная матрица попарных
  расстояний (`cosine` = `1 - cos`, иначе евклидово), затем для каждой строки
  порог — расстояние до `k`-го соседа (`k = 0` → `ceil(2√n)`); `R[i,j] = 1`
  при `dist ≤ threshold`, диагональ исключена. `sym = true` оставляет только
  взаимных соседей. **Приближение:** только бинарный выход (`mode = connectivity`);
  нет `mode = affinity`/`distance`, нет `width` (исключения ближней диагонали),
  нет самосоединения `self`.
- **`cross_similarity(A, B, metric)`** — `cosine`: косинус (сходство, не
  расстояние); иначе `exp(-‖a - b‖)` (экспоненциальное ядро расстояния,
  не гауссово ядро с квадратом нормы).
  Без порогов и kNN.
- **`recurrence_to_lag(R, pad)`** — `lag[|j - i|, i] += R[i,j]`; при `pad`
  число строк `2n`. **Расхождение с librosa:** знак лага теряется (берётся
  модуль), поэтому `lag_to_recurrence` восстанавливает симметричную матрицу и
  **не является точным обратным** для несимметричного `R`.
- **`path_enhance(R, n_filter)`** — усреднение по диагональному окну длины
  `n_filter` с центром в `(i, j)`. **Приближение:** только один диагональный
  фильтр (без набора углов `n_angles`, без `zero_mean`, без `clip`).
- **`subsegment(_data, frames, n_segments)`** — **Расхождение с docstring:**
  данные не используются; каждый сегмент длиннее `n_segments` кадров делится
  на `n_segments` равных частей. Это не агломеративная кластеризация librosa.

## 18. Утилиты

Источник: [`util/utils.rs`](../../sonara/src/util/utils.rs),
[`util/matching.rs`](../../sonara/src/util/matching.rs).

**Кадрирование и длины.**

- `frame(y, frame_length, hop)` → `(frame_length, n_frames)`, столбец `t` =
  `y[t·hop .. t·hop + frame_length]`, копирование (не view). Без центрирования.
- `pad_center(data, size)` — нули по краям, левый отступ `(size - n)/2`.
- `fix_length(data, size)` — усечение или дополнение нулями справа.
- `fix_frames(frames, x_min, x_max)` — фильтр `< x_max`, вставка `x_min` в
  начало, сортировка, дедупликация. **Приближение:** `x_max` **не** добавляется
  в конец, в отличие от librosa при `pad = true`.
- `expand_to(x, ndim, axis)` — вставка единичных осей.

**Нормировка и пики.**

- `normalize(data, norm, threshold)` — деление на `l1`/`l2`/`max|inf`;
  делитель не меньше `threshold` (по умолчанию `f32::MIN_POSITIVE`). Только
  1-D; норм `-inf`/`p` нет, `fill` нет.
- `localmax` / `localmin` — строгие экстремумы с соседями; края `false`.
- `peak_pick(x, pre_max, post_max, pre_avg, post_avg, delta, wait)` — три
  условия: `x[n]` равен максимуму окна `[n - pre_max, n + post_max]` (с
  допуском `1e-15`), `x[n] ≥ mean(окно avg) + delta`, и `n - last_peak ≥ wait`.
  **Приближение:** в librosa окна максимума и среднего берутся асимметрично
  с `post_*` невключительно; здесь `post` включён. Плато с одинаковыми
  значениями дают пик на первой позиции, удовлетворяющей `wait`.
- `softmask(x, ref, power)` — `|x|^p / (|x|^p + |ref|^p)` с защитой `tiny`;
  без опции `split_zeros`.
- `sync(data, frames, aggregate)` — агрегация по сегментам между границами
  `[0, frames…, n_cols]`, поддерживаются `mean`/`max`/`min` (**медианы нет**);
  выход всегда `(rows, len(frames) + 1)`, даже если последняя граница совпала с
  `n_cols` (тогда последний столбец — нули).
- `tiny`, `abs2*`, `phasor*`, `valid_audio`, `valid_int`, `valid_intervals`,
  `dtype_r2c`/`dtype_c2r` — мелкие помощники; `valid_audio` проверяет
  непустоту и конечность.

**Сопоставление событий.**

- `match_intervals(from, to)` — для каждой строки `from` индекс интервала `to`
  с максимальным индексом Жаккара `|∩| / |∪|`; O(`n·m`). **Приближение:**
  нет `strict`-режима и обработки непересекающихся интервалов (там вернётся
  первый с Жаккаром 0).
- `match_events(from, to)` — ближайший по модулю разности; O(`n·m`) без
  сортировки. **Приближение:** нет флагов `left`/`right`.

## 19. Сводка расхождений

Собрано в одном месте, чтобы даунстрим мог быстро оценить, чему доверять.
«Приближение» — упрощение с известными последствиями; «Расхождение» —
поведение противоречит docstring или ожидаемой семантике.

| Где | Тип | Суть |
| --- | --- | --- |
| `core/pitch.rs` `pyin` | Расхождение | `period = min_period + lag` при абсолютном `lag` — f0 систематически занижен; тест не ловит |
| `core/spectrum.rs` `iirt` | Расхождение | не фильтрует: все полосы = энергия кадра |
| `core/spectrum.rs` `reassigned_spectrogram` | Расхождение | обычный power-спектр |
| `core/audio.rs` `lpc` | Расхождение | Левинсон-Дурбин, а не Бург |
| `core/constantq.rs` `vqt` | Приближение | прореживание без антиалиасинга; только при чётном `hop` |
| `core/constantq.rs` `pseudo_cqt`, `hybrid_cqt` | Расхождение | оба = полный `cqt` |
| `core/constantq.rs` `icqt` | Приближение | сопряжённая транспозиция вместо псевдообратной |
| `feature/spectral.rs` `poly_features` | Расхождение | моменты, не коэффициенты полинома |
| `feature/spectral.rs` `spectral_contrast` | Приближение | лог-сетка полос вместо октавной; последняя строка — `log10(mean)` |
| `feature/spectral.rs` `tonnetz` | Приближение | единичные радиусы для всех трёх кругов |
| `feature/inverse.rs` `mel_to_stft` | Приближение | 50 шагов для NNLS без проверки сходимости |
| `decompose.rs` `hpss` | Приближение | `margin` сокращается и не влияет на маску |
| `sequence.rs` `viterbi_discriminative` | Расхождение | = `viterbi` |
| `sequence.rs` `transition_loop` | Приближение | `1 - p` только на `i + 1` |
| `sequence.rs` `rqa` | Приближение | длина диагоналей без gap-штрафов |
| `segment.rs` `recurrence_to_lag` | Расхождение | знак лага теряется; обратное преобразование неточно |
| `segment.rs` `subsegment` | Расхождение | равномерное деление, данные игнорируются |
| `filters.rs` `cq_to_chroma` | Приближение | `i mod n_chroma`, `bpo`/`fmin` игнорируются |
| `filters.rs` `constant_q_lengths` | Расхождение | не используется CQT; там длина без полосы окна |
| `dsp/windows.rs` `gaussian` | Расхождение | `std` в долях полудлины, не в отсчётах |
| `dsp/iir.rs` `filtfilt` | Приближение | без `lfilter_zi`, только отражение краёв |
| `core/pitch.rs` `pitch_tuning` | Приближение | медиана вместо гистограммы; `resolution` не используется |
| `core/harmonic.rs` `salience` | Приближение | ближайший бин, O(`n_bins²`) |
| `core/intervals.rs` `plimit_intervals` | Приближение | усечение по значению, не по Tenney height |
| `core/spectrum.rs` `pcen` | Приближение | `exp(-1/T)` вместо формулы librosa |
| `types.rs` `PadMode` | Приближение | `Symmetric`/`LinearRamp` парсятся, но в `stft` = нули |

Таблица не является исчерпывающим аудитом корректности: отсутствие алгоритма
в ней не гарантирует полную совместимость с другой библиотекой или стандартом.
Численные допуски и поведение на границах нужно проверять под свою задачу.
Помните, что `analyze.rs` использует собственный слитный проход
([README](../../README.md#analysis-pipeline), [api.md](api.md)); значения в
`TrackAnalysis` могут отличаться от модульных функций, если их параметры
(например `n_fft`, `hop`, нормировка chroma) различаются.
